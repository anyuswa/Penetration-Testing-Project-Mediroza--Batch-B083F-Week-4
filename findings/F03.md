# F03 | Internal backup location leaked in PDF metadata

| Field | Value |
| --- | --- |
| Risk | Medium |
| Status | Open - retest pending |
| Milestone | M3 |
| Affected asset | patient_report_3.pdf metadata /Comments and /Author |
| Evidence references | E38, E40; see [evidence register](../evidence/EVIDENCE_INDEX.md) |

## Observation and proof

The third PDF contains an internal author identifier and an internal comment disclosing a legacy backup directory. This was recorded through metadata/string inspection and independently confirmed in the locally decrypted uploaded PDF. The clue led to the [legacy archive]/ directory response.

## Interpretation

Operational notes and an internal account identifier were included in a distributed patient document. Metadata disclosed a server path that should not be exposed through client documents.

## Demonstrated impact

The leak reduced the effort required to locate the archive that contained HR and shareholder data. It does not itself grant server access; the separate public backup exposure is rated under F04.

## Remediation

Apply a metadata allowlist to document generation, remove internal comments and usernames, and inspect all distributed documents and historical copies for similar disclosures. Avoid storing infrastructure notes in patient documents.

## Retest acceptance criteria

Inspect generated files using at least two metadata parsers and confirm operational comments, filesystem hints and account identifiers are absent.

## Publication qualification

Original screenshots and sensitive values are withheld from this public copy. The confidential reference report retains the supporting material. This record documents the authorised exercise and does not claim a new live verification.
