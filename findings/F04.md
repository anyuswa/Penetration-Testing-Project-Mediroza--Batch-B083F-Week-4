## Observation and proof

The supplied curl output for [legacy archive]/ shows HTTP/2 200 and Index of [legacy archive]/, linking the SQL backup. Download evidence records 6,346 bytes; file inspection identifies ASCII text. The SQL excerpts show staff and shareholders tables with 30 employees and 10 shareholders.

## Interpretation

The archive was kept in a web-served directory and exposed through autoindex. Disabling listing alone would still leave a known file URL reachable; both storage and access controls require correction.

## Demonstrated impact

Bulk disclosure includes names, jobs, departments, emails, phones, national IDs, monthly salaries, joining dates and ownership details. This is direct evidence of confidential data exposure, with no database credentials or host takeover demonstrated.

## Remediation

Remove the backup from web-accessible storage, block legacy archive routes and disable directory indexing. Store encrypted backups outside the document root with restrictive access, defined retention and access logging. Review web logs for prior archive retrieval and identify other exposed backups.

## Retest acceptance criteria

Confirm [legacy archive]/ has no listing and the exact known backup URL is denied to unauthenticated and ordinary users. Verify the file is removed from origin, cache and deployment artifacts; confirm new backups cannot be published by the deployment process.
